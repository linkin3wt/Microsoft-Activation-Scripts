# 文件翻译应用方案（中文）

## 1. 目标
构建一个“上传即翻译”的应用：
- 支持上传：PDF、DOCX、XLSX、图片（PNG/JPG/JPEG/TIFF/BMP）。
- 输出文件类型与原文件一致。
- 支持两种输出模式：
  1. **纯翻译模式**（仅中文译文）
  2. **原文+译文对照模式**（分段对照）

---

## 2. 推荐技术栈（MVP）
- **后端 API**：FastAPI
- **任务队列**：Celery + Redis（异步处理大文件）
- **对象存储**：S3/MinIO（保存上传与结果文件）
- **文档解析/生成**：
  - PDF：PyMuPDF / pdfplumber（文本），OCR 场景配合 Tesseract
  - DOCX：python-docx
  - XLSX：openpyxl
  - 图片：Pillow + Tesseract OCR
- **翻译引擎**：
  - 云 API（如 OpenAI / DeepL / Azure Translator）
  - 本地模型（可选，满足私有部署）
- **前端**：React + Ant Design（上传、进度、下载）

---

## 3. 系统架构
1. 用户上传文件并选择模式（纯翻译/对照）。
2. 后端识别文件类型，进入对应解析管道。
3. 文本切分（按段落/单元格/页面）并做术语预处理。
4. 调用翻译服务，输出中文文本。
5. 根据模式重组文档：
   - 纯翻译：替换为中文
   - 对照：保留原文并插入译文（段后/相邻列）
6. 生成与原始相同扩展名文件并返回下载链接。

---

## 4. 不同文件类型实现策略

### 4.1 PDF
- **可复制文本 PDF**：抽取文本块 -> 翻译 -> 重新排版生成 PDF。
- **扫描件 PDF**：先 OCR -> 翻译 -> 生成带文本层或对照版 PDF。
- 对照模式可采用“原文段落 + 译文段落”双段结构，减少版式错乱。

### 4.2 DOCX
- 遍历段落、表格、页眉页脚、批注（可选）。
- 纯翻译：替换 run/paragraph 文本。
- 对照：在段后追加 `【中文】` 段落，保留样式映射。

### 4.3 XLSX
- 按工作表遍历单元格，仅处理字符串类型。
- 纯翻译：覆盖原单元格。
- 对照：在右侧新建“译文列”（如 B->C、D->E），或新增 `_CN` 工作表。

### 4.4 图片
- OCR 获取文本框坐标。
- 纯翻译：文字擦除后按坐标回填中文。
- 对照：保留原图并附加底部译文区域，或导出双页 PDF（原图页 + 译文页）。

## 5. API 设计（示例）

### `POST /api/v1/jobs`
- form-data:
  - `file`: 上传文件
  - `mode`: `translate_only` | `bilingual`
  - `source_lang`: `auto`
  - `target_lang`: `zh`
- 返回：`job_id`

### `GET /api/v1/jobs/{job_id}`
- 返回任务状态：`queued/running/succeeded/failed`、进度、错误信息

### `GET /api/v1/jobs/{job_id}/download`
- 任务成功后下载结果文件（扩展名与原文件一致）

---

## 6. 核心数据模型（建议）
- `jobs`：任务元信息（用户、模式、状态、时长）
- `job_files`：原文件路径、结果文件路径、MIME、大小
- `job_segments`：分段文本、译文、坐标/位置信息、顺序
- `glossaries`（可选）：术语库（行业词统一）

---

## 7. 关键工程点
1. **长文切分与上下文一致性**：按段落 + 上下文窗口翻译，避免术语漂移。
2. **格式保真**：优先保留样式与结构，不强求像素级一致。
3. **失败可恢复**：每段翻译结果落库，失败后可续跑。
4. **并发与限流**：队列并发 + 单用户配额，防止大文件压垮服务。
5. **安全**：
   - 文件杀毒扫描
   - 白名单扩展名与 MIME 双校验
   - 临时文件过期删除

## 8. 里程碑（4 周 MVP）
- **第 1 周**：上传/下载流程、任务队列、状态查询
- **第 2 周**：DOCX/XLSX 完整翻译链路（纯翻译+对照）
- **第 3 周**：PDF（文本型）+ 图片 OCR
- **第 4 周**：权限、监控、错误重试、部署上线
